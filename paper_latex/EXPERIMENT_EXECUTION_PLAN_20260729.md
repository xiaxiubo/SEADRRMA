# TRACE 论文实验执行清单

## 1. 审阅范围与核心证据链

本清单根据当前主稿及其实际包含文件整理：

```text
paper_TRACE_title_intro.tex
simulation_sections_revised.tex
discussion_revised.tex
IMPROVEMENT_PLAN.md
HARDWARE_EXPERIMENT_PLAN.md
```

论文需要依次回答四个核心问题：

1. TRACE 是否在惯量突变时优于现有控制器？
2. 显式快速惯量估计是否确实提供了额外价值？
3. Fast/Slow、双时间尺度注意力、融合门和 DAgger 是否分别必要？
4. 仿真优势能否在真实 SEA 和 200 Hz Orin 控制系统中复现？

---

## 2. 对比标签说明

| 标签 | 需要运行的方法 |
|---|---|
| **[全算法对比]** | TRACE、RMA、PPO、PD+DOB、LQR |
| **[学习算法对比]** | TRACE、RMA、PPO |

RMA 和 PPO 是算法基线，不应继续被称为严格的组件消融。

## 3. 实验前必须冻结的统一条件

### P0. 物理和软件版本冻结 **[无算法对比]**

- 弹簧刚度固定为 `2400 Nm/rad`。
- 统一电机侧和负载侧 Stribeck、库仑和粘性摩擦定义。
- 修正负载速度：`load_vel = motor_vel + spring_vel`。
- 检查负载摩擦在 MuJoCo 中的广义力映射。
- 固定控制频率 `200 Hz`、力矩限制、观察归一化和安全限制。
- 保存每个模型的 checkpoint、ONNX、代码 commit 和配置 JSON。

这一步完成前，不应生成论文最终对比表。

### P1. 基线公平性冻结 **[所有基线]**

- PPO 和 RMA 使用与 TRACE 相同的训练物理域、基础奖励和训练数据范围。
- PPO、RMA 和 TRACE 至少报告参数量、训练步数、训练 seed 和模型选择规则。
- PD+DOB 和 LQR 在独立调参集上调参，不能使用最终测试轨迹反复调参。
- 固定每种算法的最大调参次数或调参时间预算。
- 所有算法使用相同参考轨迹、初始状态、惯量变化、限幅和采样频率。

若新 TRACE 使用了更新后的摩擦模型，旧 PPO/RMA checkpoint 不可直接作为
最终公平基线，除非验证其训练物理域完全一致。

## 4. 仿真实验

### S1. 主惯量突变基准 **[全算法对比，必须]**

```text
Reference: qd = 0.5 sin(2 pi 0.3 t) rad
Inertia:   0.3 -> 0.05 -> 0.75 kg m^2
Events:    t = 3 s and 7 s
```

目的：

- 支撑摘要和结论中的主要性能数字。
- 比较整体跟踪、释放瞬态和重新加载瞬态。

指标：

- 全时段位置 RMSE。
- 两个事件后 `0.5 s` RMSE。
- 最大绝对误差。
- 力矩 RMS。
- `RMS(Delta torque)`。
- 饱和率和终止率。
- 事件后恢复时间。

输出：

- 一张五算法位置、误差、力矩和惯量估计主图。
- 一张五算法指标表。

状态：当前论文已有旧结果，但新算法和新物理参数完成后必须整体重跑。

### S2. 固定惯量性能矩阵 **[全算法对比，必须]**

建议惯量：

```text
J = 0.05, 0.30, 0.45, 0.75 kg m^2
```

建议轨迹：

```text
A = 0.3 and 0.5 rad
f = 0.3 and 0.5 Hz
```

目的：

- 证明优势不是只来自单个惯量切换轨迹。
- 检查不同算法在低惯量和高惯量下的稳定性与调参偏置。

主文可只展示 `J=0.05/0.30/0.75` 汇总，完整矩阵放补充材料。

### S3. 惯量切换方向与幅值矩阵 **[学习算法对比，重要]**

至少包括：

```text
0.30 -> 0.05
0.05 -> 0.30
0.30 -> 0.75
0.05 -> 0.75
0.75 -> 0.05
```

目的：

- 检验上升和下降切换的不对称性。
- 避免只使用论文主轨迹得出普遍结论。

PD+DOB 和 LQR 可只在主序列 S1 中完整展示，S3 重点比较 TRACE、RMA 和 PPO。

### S4. 轨迹和激励强度泛化 **[学习算法对比，重要]**

轨迹建议：

- 低幅正弦：`A=0.1 rad`。
- 标称正弦：`A=0.3/0.5 rad`。
- 频率扫描：`f=0.1, 0.3, 0.5, 0.8 Hz`。
- 多正弦轨迹。
- 梯形速度轨迹。
- 平滑点到点轨迹。
- 阶跃参考仅作为失败边界，不作为主要性能场景。

目的：

- 支撑论文关于历史激励和弱可观测性的边界讨论。
- 观察低幅、低加速度情况下的惯量估计退化。

### S5. 摩擦与模型失配鲁棒性 **[学习算法对比，重要]**

使用新 Stribeck 模型独立随机化：

- 电机侧 `Fc/Fs/B`。
- 负载侧 `Fc/Fs/B`。
- 正反向摩擦不对称。
- 弹簧刚度偏差。
- 温度或运行历史引起的摩擦整体缩放。

比较 TRACE、RMA 和 PPO。传统控制器在标称值和两个边界点运行即可。

输出：

- 跟踪 RMSE 热力图。
- 惯量估计 RMSE 热力图。
- 最差条件及失败原因表。

当前 108 条件套件只变化负载库仑摩擦和负载粘性阻尼，重新训练后应改为与
实物摩擦证据一致的范围。

### S6. 传感器和执行链路非理想因素 **[精选对比，重要]**

至少加入：

- 编码器量化。
- 测量噪声。
- 速度差分噪声。
- 力矩比例误差。
- 1--2 个控制周期的动作延迟。
- EtherCAT 周期抖动。
- 离合器动作延迟。
- 未建模弹性和齿隙。

比较 TRACE、RMA 和 PD+DOB，报告性能退化曲线，而不是只报告一个噪声点。

### S7. 统计重复性 **[全算法对比，必须]**

最低要求：

- 每种学习算法至少 `3` 个独立训练 seed，推荐 `5` 个。
- 每个固定模型至少 `10` 个评价 seed 或初始条件。
- 报告均值、标准差和单次最差结果。

若计算预算不足，只能使用单训练 seed，则必须明确写为限制，不能把多个评价
episode 当作独立训练重复。

## 5. TRACE 组件消融

### A1. 核心结构消融 **[TRACE 消融，必须]**

在同一个 teacher actor 和相同数据上比较：

1. 完整 TRACE。
2. 固定标称惯量，无 Fast、无 Slow。
3. 仅 Fast，无 Slow TCN。
4. 仅 Slow TCN，无显式惯量估计。
5. 单一 RMA 式 latent。

该实验回答 Fast 和 Slow 两个分支是否分别必要。

### A2. Fast Attention v2 消融 **[TRACE 消融，必须]**

1. 完整短头+长头+学习融合。
2. 仅短时间尺度头。
3. 仅长时间尺度头。
4. 固定 `0.5/0.5` 融合。
5. 无 jump gate。
6. 硬 confidence hold。
7. raw bounded output。

指标同时报告：

- 惯量稳定段 RMSE。
- 切换峰值误差。
- 惯量估计恢复时间。
- 闭环跟踪 RMSE。

### A3. 训练流程消融 **[TRACE 消融，重要]**

1. DAgger 前。
2. DAgger 后。
3. 无范围约束输出。
4. 有范围约束输出。
5. 无 rate limit。
6. 有 rate limit。

若最终新算法已经改变了结构，应根据最终结构重新定义 A2/A3，不能沿用旧
Fast Attention v2 名称但运行不同实现。

## 6. 惯量辨识专项实验

### E1. 固定惯量标定点 **[估计器对比，必须]**

真实惯量：

```text
J = 0.05, 0.30, 0.75 kg m^2
```

每个惯量运行多个幅值和频率，比较：

- TRACE Fast 原始输出。
- 传统滑窗最小二乘或 RLS。
- 可选 EKF/UKF 惯量估计器。

RMA 和 PPO 没有显式惯量输出，不应强行作为惯量辨识算法比较。

指标：

- 均值偏差。
- RMSE 和标准差。
- 正负速度方向差。
- 估计范围外尖峰。
- 弱激励区有效率。

### E2. 惯量突变辨识 **[估计器对比，必须]**

对每个切换方向报告：

- 峰值估计误差。
- `10%` 或指定误差带内的恢复时间。
- 稳定段 RMSE。
- 过冲和方向偏差。

### E3. 辨识失败边界 **[仅 TRACE + 传统估计器，重要]**

- 接近静止。
- 低幅低频。
- 高摩擦。
- 反向换向。
- 高噪声。

该实验用于支持“需要轨迹激励”的边界表述，不能声称任意静止状态下都可
辨识惯量。

## 7. 实物实验

### H0. 实物标定与安全检查 **[无算法对比，必须]**

- 三编码器方向、零偏和量化。
- 弹簧刚度 `2400 Nm/rad` 复核。
- 电机侧和负载侧静/动摩擦。
- 各砝码组合惯量。
- 离合器 ON/OFF 定义及动作延迟。
- 力矩指令与驱动反馈比例。
- 200 Hz WKC、周期和安全保护。

这些数据不能作为 TRACE 性能结果，但必须支撑实验可复现性。

### H1. 固定惯量正弦跟踪 **[全算法对比，必须]**

建议惯量：

```text
0.05, 0.30, 0.75 kg m^2
```

建议主轨迹：

```text
A = 0.3 rad, f = 0.5 Hz
```

可追加论文仿真轨迹：

```text
A = 0.5 rad, f = 0.3 Hz
```

目的：

- 确认所有基线在没有切换时都已合理调试。
- 排除某算法因基础跟踪能力差而导致的不公平比较。

每种方法、每个惯量至少重复 `5` 次。

### H2. 正弦运行中的惯量突变 **[全算法对比，核心必须]**

```text
0.30 -> 0.05 -> 0.75 kg m^2
```

这是硬件章节的主要对比实验，应运行 TRACE、RMA、PPO、PD+DOB 和 LQR。

若人工更换砝码无法在 `t=7 s` 前完成，则统一采用：

```text
t = 3 s:  0.30 -> 0.05
t = 10 s: 0.05 -> 0.75
```

同时将仿真增加一个完全相同时间序列用于 sim-to-real 对照。不能让实物使用
`3/10 s`，正文却仍写成 `3/7 s`。

每种算法建议重复 `10` 次，随机或交替算法运行顺序，减少温升和运行历史偏差。

### H3. 恒定转速下惯量突变 **[精选对比，重要]**

比较：

```text
TRACE、RMA、PD+DOB
```

建议正负方向分别测试，并使用至少两个速度，例如：

```text
|v| = 0.1 and 0.3 rad/s
```

目的：

- 模拟搬运或持续扫掠过程中放下/拿起物体。
- 检查速度维持、力矩冲击和惯量估计。

PPO 和 LQR 可不在该场景重复，以控制论文篇幅。

### H4. 惯量突变同时减速 **[仅 TRACE，建议增加 PD+DOB 参考]**

至少包括：

```text
0.30 -> 0.05 while decelerating
0.05 -> 0.75 while decelerating
```

该场景主要证明 TRACE 在安全减速任务中可运行，不作为算法优越性的主要证据。
建议增加 PD+DOB 作为传统控制参考，但不必运行全部五种算法。

### H5. 不同运动速度和轨迹 **[仅 TRACE，重要]**

- `0.2/0.3/0.5 Hz` 正弦。
- `0.1/0.3/0.5 rad` 幅值。
- 正负恒速。
- 平滑点到点轨迹。

目的：

- 证明 TRACE 不仅适用于单个 `0.3 rad, 0.5 Hz` 轨迹。

### H6. 长时间稳定性 **[仅 TRACE，重要]**

- 固定惯量连续运行至少 `10--30 min`。
- 多次离合器切换。
- 记录温度标签、WKC、周期超时、力矩和误差漂移。

无需所有基线做长时间测试。

### H7. Sim-to-real 对照 **[TRACE + 主基线，必须]**

对 H1 和 H2 使用相同参数运行仿真，比较：

- 位置误差变化。
- 力矩幅值与抖动。
- 惯量估计偏差。
- 切换恢复时间。

主文重点展示 TRACE，可在表中同时给出 RMA 和 PD+DOB 的 sim-to-real 性能变化。

## 8. 部署与实时性

### D1. 最终 ONNX 推理延迟 **[仅 TRACE，必须]**

- 使用最终训练完成的 ONNX。
- Jetson Orin 上测试 1/2/4 CPU 线程。
- 至少 500 次预热和 5000 次正式测量。
- 报告 mean、P95、P99、max 和 `>5 ms` 次数。

### D2. 完整 200 Hz 控制周期 **[仅 TRACE，必须]**

推理时间不能替代完整周期时间。实物运行需要同时记录：

- EtherCAT 收发。
- 观测构造。
- ONNX 推理。
- 安全检查。
- 日志写入。
- 完整循环周期。

报告周期 mean、P99、max、deadline misses 和 WKC。

## 9. 可以在新 TRACE 训练完成前先做的工作

### 可以立即进行

1. 完成 PPO、RMA、PD+DOB 和 LQR 的版本冻结及部署接口检查。
2. 在独立调参轨迹上完成 PD+DOB 和 LQR 的公平调参。
3. 对所有基线依次完成低幅、低速、固定 `J=0.05` 的安全测试。
4. 完成 H1 固定惯量基线数据采集。
5. 完成 H3 恒速场景下 RMA 和 PD+DOB 数据采集。
6. 若硬件协议已经冻结，可提前采集 H2 的四个基线。
7. 准备 RLS/EKF 等传统惯量估计器，之后可离线处理同一批日志。
8. 完成 H0 标定、离合器延迟和完整周期测量。

### 暂时不能形成最终论文结论

1. 不能将新 TRACE 与旧物理参数下的 PPO/RMA 直接比较。
2. 不能在新 TRACE 尚未完成时确定最终排名或提升百分比。
3. 不能把单次硬件运行作为统计结果。
4. 不能把当前闭环物理补偿惯量估计冒充新的 TRACE Fast 原始输出。

## 11. 统一统计指标

控制性能：

- Tracking RMSE。
- Maximum absolute error。
- Post-event RMSE。
- Recovery time。
- Torque RMS。
- `RMS(Delta torque)`。
- Saturation rate。
- Safety-trigger/termination rate。

惯量估计：

- Stable-segment RMSE。
- Mean bias。
- Standard deviation。
- Peak transient error。
- Settling time。
- Positive/negative velocity direction gap。
- Out-of-range rate。

实时系统：

- Inference mean/P99/max。
- Full-cycle mean/P99/max。
- Deadline-miss rate。
- WKC failure count。

## 13. 当前最高优先级

1. **立即**：冻结统一物理模型和基线公平性协议。
2. **新 TRACE 训练期间**：完成四种基线的 H1、H3 和可执行的 H2 数据。
3. **新 TRACE 完成后**：重跑 S1、S2、S5、A1/A2 和最终 Orin 延迟。
4. **实物核心证据**：完成 H2 五算法各 10 次重复。
5. **惯量辨识证据**：完成 E1/E2，并加入 RLS/EKF 对照。
6. **最后**：根据最终数据重写摘要、结果、讨论和结论中的全部数值。
